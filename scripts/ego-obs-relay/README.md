# ego → OBS 干净画面转播

从现有 ego 页面取得画面，通过仅本机可访问的服务送入 OBS。画面不包含 ego 的蓝色控制遮罩、浏览器工具栏和 Agent 鼠标。不会导航、点击、修改页面尺寸或接管已有任务。

## 启动

在项目目录运行（需要 Node.js 和已安装的 `ego-browser`）：

```sh
node scripts/ego-obs-relay/server.mjs --space 0 --page p1
```

本次连接的是「Akagi 直播」的雀魂页面（Space 0 / p1）。重启 ego 后编号可能变化；以当前任务的编号为准。目标 Space 必须已处于 Agent 控制状态；转播程序不会强行接管。

## OBS 设置

- 新建「浏览器」源，URL：`http://127.0.0.1:17362/obs`。
- 本次初始画面为 1920 × 934，可填同样的宽高。源页面会按比例完整显示画面，尺寸变化时可能出现黑边。
- 需要查看最新分辨率和帧率时打开 `http://127.0.0.1:17362/stats`。
- 转播只提供画面；声音继续使用原有的 macOS 音频采集。
- 本次已添加到测试场景「Akagi」的浏览器源，在工作室模式的左侧预览。原有直播场景保持在右侧输出，尚未转场。

## 参数和停止

```sh
node scripts/ego-obs-relay/server.mjs --space 0 --page p1 --port 17362 --fps 30 --width 1920 --quality 80
```

`--fps` 是目标上限，实际帧率取决于页面更新和浏览器负载。主路径使用 CDP screencast；启动 3 秒内没有收到帧时回退到串行截图。截图回退路径不应用 `--width` 缩放，按原页面分辨率输出。静止页面可能不会持续生成新帧。

在运行转播的终端按 Ctrl+C 停止；不会结束原有自动对局。退出 ego、页面关闭或用户拿回控制权时，转播可能停止，需要在目标页面恢复 Agent 控制后重新启动。`/stats` 中的 `workerExit` 可用于判断采集进程是否已退出。转播中断时画面可能停在最后一帧。

服务只监听 `127.0.0.1`，不上传画面。只保留最新帧，慢速观看端会跳帧，避免不断积累延迟。不要同时为同一个页面启动多个转播实例。

## 验证记录

2026-11-07，ego lite 0.6.2.5、OBS 33.0.1、macOS：已验证实际雀魂页面的 screencast 持续输出，并在 OBS 浏览器源中看到动态游戏画面，没有蓝色遮罩。调整帧调度后，短时测得约 29.8 fps，重启服务后 OBS 自动恢复连接。页面尺寸变化时也继续输出（本次观察到 1920 × 934 和 1920 × 866）。没有测定端到端延迟及长时间无人值守运行的稳定性。
