## 1. 实施顺序

先实现状态可信与外部动作边界，再接 AI 和直播。每个阶段都保留可运行入口和明确的验证记录；未通过的关键门槛不得用下一阶段功能掩盖。

| 阶段 | 实现内容 | 阶段完成证据 |
| --- | --- | --- |
| 0. 技术验证与固定版本 | 验证 ego 持续采集／同步／发送、当前协议字段、Akagi arm64 runner、模型并发、系统语音与 OBS 路径；固定运行时与依赖版本，登记源码和模型许可 | `docs/validation/technical-spikes.md`；每项含环境、版本、实测、限制和采用结论 |
| 1. 状态与执行基础 | TypeScript 工程、配置校验、SQLite 迁移、GameActor、脱敏采集、reducer、同步、动作窗口与单执行器；CLI 提供 replay／inspect／预演 | 脱敏样本可确定性重放；关键字段与客户端一致；弃牌与同步实测通过；未知状态关闭执行 |
| 2. 完整游戏与双模式 | 房间流程、自动和牌、鸣牌与立直映射、Rust runner、LLM provider、本地规则、上下文隔离、限额与同房续局 | 两种模式分别完成实际整场；小局切换与连庄隔离通过；所有关键动作有实际或代表性回放证据 |
| 3. 可信解说与语音 | 每次己方弃牌事实档案、解释契约、历史追问、角色、禁词、live worker、TTS、播放与合并 | 逐手文字覆盖；语音忙时游戏继续；实际播完确认；积压与跨局回顾验证；音轨可分别调节 |
| 4. 弹幕与控制页面 | B站消息适配、去重与自身识别、问答选择、统一发送出口、控制台、OBS 投影与重连 | 模拟与真实收发均验证；选中互动能口播＋短文字；预演和禁词无绕行；OBS 无控制凭证 |
| 5. 连续运行与交付 | 三场／60 分钟限制、同房再开、暂停接管、故障恢复、保留清理、使用说明与试播 | 至少一场完整四人东＋同房再次开局；输出可追溯；无重复动作／过期播报；未覆盖分支明确登记 |

阶段 3、4 可以使用阶段 1 的新样本推进模块开发，但未通过游戏恢复门槛前不能进行无人值守运行。

所有样本、回放器和验证记录重新建立；历史“10 项测试通过”不计入新工程测试数量。阶段 0 只验证最小必要链路，不提前搭建完整 Live2D／VRM 前端。

### 可选角色里程碑

Live2D 优先复用现有 VTB 前端，按 [LIVE2D.md 的 L0—L3](../research/LIVE2D.md#10-最小实施与验收) 单独推进：固定版本／角色 → 单句音频与口型 → 接唯一调度与租约 → OBS 连续验证。L0 可独立进行；L1 依赖阶段 3 的音频产物与完成语义；L2 依赖稳定的播报队列并补齐浏览器传输契约；L3 结合阶段 4 的 OBS 验证。

这一里程碑不改变阶段 0—5 的基础交付范围。角色功能只有通过对应验证后才启用；复用代码、资源和补丁版本登记在上游清单，不能将源码中“存在此功能”写成已联调通过。

## 2. 技术验证门槛与失败出口

| 门槛 | 必须回答 | 未通过时的处理 |
| --- | --- | --- |
| ego 桥接 | 能否连续获得消息？如何检测断线／漏包？最终发送点能否校验暂停代际？UI 开关能否读回？ | 更换或补强适配方式并更新架构；保留离线实现，暂停真实自动操作 |
| 当前协议 | 规则、小局边界、实际动作、完整同步、单步截止时间和源去重依据分别来自哪里？ | 未知关键字段暂停；不套用历史 4.0.51 或上游版本号作为当前结论 |
| Akagi runner | 能否在当前 Mac 编译／装载模型？CPU 延迟是否留足提交预算？红五／立直／鸣牌能否唯一映射？ | 修正封装或重新选择引擎；可先推进 LLM 和本地规则，但双模式验收仍未完成 |
| 本地规则 | 是否能在预算内为当前合法集合给出有效动作？安全性与向听／进张来源是否可解释？ | 缩小计算、补充已验证算法；规则失败时关闭程序提交，不宣称已具备可靠降级 |
| 模型服务 | 是否支持配置的 JSON 模式、超时和并发？一个服务是否足以保留决策名额？ | 严格解析；缩短预算；并发不足时限制直播 LLM 或配置独立服务 |
| B站消息 | 稳定身份与消息 ID 是否存在？自身消息如何识别？发送回执和平台约束是什么？ | 使用替代消息源或限制能力，记录身份／补发缺口；不以匿名连接当作收发闭环 |
| 中文语音 | 选中声音是否安装？合成格式、取消、播放完成能否确认？ | 调整合成与转换适配；文字继续，语音不得标记验收通过 |
| OBS 音轨 | 当前系统是否能分别调节游戏与语音？页面重连是否重复播音？ | 调整独立输出设备或切换浏览器音频适配；只能启用一个播放端 |
| 上游许可与版本 | 代码、模型文件、可选角色资源分别如何使用／分发？ | 先记录并澄清所用材料的许可；不能只看 README 或 package 字段便声称可分发 |

版本清单至少包括：本机系统与架构、Node 小版本、TypeScript 和 SQLite 驱动、锁文件、雀魂实际客户端／协议版本、上游 commit、模型摘要、runner 协议版本、回放 schema／reducer 版本、TTS 声音与音频格式。

## 3. 需求到模块的追踪

| 需求 | 主要模型／模块 | 关键验收证据 |
| --- | --- | --- |
| 指定四人东友人房、三个电脑、300＋0 | `FriendRoom`、RunCoordinator、GamePort | 页面规则读回与协议记录一致；不误进其他房型 |
| 所有客户端可选操作、自动和牌 | `LegalAction`、OperationWindow、GameAdapter | 吃碰杠／立直弃牌／特殊动作映射；自动和牌无竞争发送 |
| 网络状态和接口执行、事件确认 | `GameState`、ActionAttempt、GameActor、ActionExecutor | 回执与权威确认分离；断线后不重复动作 |
| 专用引擎／LLM，每小局切换 | `Hand.activeMode`、DecisionProvider | 当前／下小局模式分别展示；连庄创建新上下文 |
| 顺位优先、重视避四 | `DecisionSnapshot`、引擎／LLM 输入、规则证据 | 比分与场况确实进入请求；不以几场胜负证明牌力 |
| 每次弃牌的简短文字解释 | `ObservedAction`、Explanation、outbox | 所有己方弃牌都有唯一文字关联；失败也有事实模板 |
| 观众聊天更密集且优先 | ViewerMessage、InteractionTurn、LiveDirector | 初值 5 秒／30 秒可调；问答优先于待播普通讲解 |
| 中文语音可替换、不阻塞游戏 | SpeechPort、SpeechTask、SpeechController | TTS／播放失败与长队列不影响出牌；播完有实际确认 |
| 本地可编辑人设和统一禁词 | 配置修订、Content、统一过滤管线 | 输入／用户名／字幕／语音／回弹幕同源过滤；热更新重检 |
| 历史追问、牌理准确 | DecisionRecord、DecisionEvidence、历史查询 | 根据旧快照解释；概率与模型偏好分开，缺证据就说明限制 |
| 独立控制台和 OBS 页面 | RunCoordinator、ProjectionService、HTTP／SSE | 开始／暂停／恢复／整场停止可用；OBS 只读与过期状态标记 |
| 默认最多 3 场或 60 分钟，同房续局 | RunSession、Match、运行限额 | 首先触达即锁存；当前整场结束后停止，不解散房间 |
| 状态故障暂停、AI 故障本地降级 | trust、controlEpoch、同步与规则 worker | 不可信不执行；可信超时走同一合法候选和执行器 |
| 日志保留 7 天，不含凭证 | SQLite、RetentionService、脱敏投影 | 清理关系完整、活动记录不删；密钥／Cookie／认证帧不落盘 |
| 无 DSH 依赖 | 模块与依赖清单 | 不依赖 DSH 宿主启动 |

## 4. 必要测试与证据分层

测试集中在状态、模型契约和真实外部副作用边界，不为每个配置字段或薄包装函数重复写实现镜像测试。

| 层次 | 内容 | 能证明什么 |
| --- | --- | --- |
| 纯逻辑测试 | reducer、不变量、候选／红五／座位、预算与限额、上下文重置 | 给定输入下的确定行为 |
| 契约测试 | HTTP／OpenAPI、SSE、命令幂等、runner RPC、LLM 输出、GamePort、B站归一化、TTS／播放器 | 模块对接口、版本、错误与确认语义的处理 |
| 回放与故障注入 | 新采集脱敏样本、重排／缺失事件、超时／崩溃、恢复 | 复杂时序下不越界执行，档案与输出可追溯 |
| 当前客户端联调 | 真实友人场、具体操作分支、同步、同房再开 | 当前版本实际兼容性 |
| 直播联调 | 模拟后真实弹幕、中文语音、OBS 本地预览／录制，再实际直播 | 真实渠道收发、播音和呈现 |

单元通过不能替代当前客户端联调；回放中出现过某动作不能写成实际牌局已触发。每个验证条目记录证据类型，并保留未覆盖分支。

### 游戏与动作边界案例

- 同一个出牌事件重复收到，局面只推进一次；缺失关键事件后关闭执行并请求同步。
- 红五与普通五分开；多个吃牌组合、明／暗／加杠、立直与具体弃牌都能唯一映射。
- 模型返回不存在的候选、自由文本或缺参数动作，严格拒绝并按可信度与预算处理。
- LLM／引擎迟到、本地规则先完成、他家事件推进局面、自动和牌先完成，原结果均不可再次提交。
- 暂停发生在冻结后、持久化等待中、桥接发送前和发送后：未发命令停止，已发命令对账，恢复不重发旧快照。
- 立直多步骤中断、桥接超时、权威确认丢失、发送前后进程崩溃，均保留未决状态并先同步。
- 重连仍在同一小局时不换模式；连庄／新小局清空出牌上下文；旧引擎任务无效。
- 状态不可信时即使模型有结果也不执行；可信但本地规则失败或预算耗尽时不强行发送。
- 达到 3 场／60 分钟时不启下一整场；整场结算重复事件不重复计数；重启恢复不清空原限额进度。

### 直播与内容边界案例

- 每个己方弃牌都有文字，解释失败、worker 重启和队列拥堵也不漏记／重记。
- 观众问上一手，引用上一手冻结记录；歧义问题不拼接当前手牌编造原因。
- 逐条弹幕去重、源断线回放、同观众重复内容、自己发出的回声、身份缺失都有明确行为。
- 输入用户名、正文、生成内容和所有输出均检查；配置热更新后旧音频废弃并重合成或取消。
- 普通解说积压可合并；新小局旧语音只能作为回顾；选中聊天不被连续解说饿死。
- 系统故障说明限频；观众提示注入不能变更配置或触发游戏／系统工具。
- 模型请求超时、合成迟到、静音和播放中断不能导致取消任务复活；一个时刻一个声音。
- 弹幕预演覆盖所有发送路径；发送超时不自动重发，短回复按独立长度和禁词规则检查。
- OBS 重连恢复最新投影；慢页面不阻塞游戏；可选浏览器音频租约防止多个页面同时播放。
- 启用 Live2D 时另验模型缺失／无 Talk 动作、音频播放拒绝、实际开始与结束、清队列保留当前句、静音闭嘴、旧代际回执、失联租约停播及双页面竞争；具体场景见专题。
- clear 取消待播但保留当前句，mute 停止当前声音；队列与播放代际分别验证，预演不计入真实发送。
- 同 commandId 重试、不同请求复用 ID、命令过期、配置／运行版本冲突、SSE 续传间隙和 reset 均按接口契约验证。
- 日志清理不删除活动整场和在播文件；脱敏导出不含认证帧、Cookie、密钥或隐藏牌。

### 时间相关参数

首轮只固定产品要求中的 3 场、60 分钟、7 天，以及试播初值 5 秒／30 秒和短回复 20 字。动作安全预留、引擎超时、队列容量、音频过期、重连退避等在技术验证中测量后配置，并记录选值依据；不能把设计中的占位值当成游戏服务器规则。

对“立即暂停”和模型超时的验证使用受控时序与故障注入；不靠随机等待碰运气。真实对局记录动作截止时间来源、提交时间和权威确认时间，衡量实际预算余量。

## 6. 完成标准

代码交付时应具备可启动的新工程、固定版本与许可清单、配置示例、本机控制台、OBS 页面、脱敏回放资产、验证记录和使用／接管说明。

产品完成至少需要：两种模式各完成真实整场；确认同房续局；所有己方弃牌有可追溯文字；选中弹幕可回答、口播并短文字回发；游戏不被语音和聊天阻塞；暂停恢复、未决提交、跨局任务与运行上限验证通过。实际直播前先通过 OBS 本地预览／录制。

未实际触发的罕见动作可先以代表性回放验证，必须在记录中标为未实场覆盖。若关键执行／同步分支仍无法确认，或语音、弹幕任一闭环未完成，应明确列为尚未交付，不以界面可见或单次弃牌成功替代验收。
