## 硬件采集性能

正式浏览器切换硬件后，现有 `everyNthFrame: 2` 转播稳定为 15.0–15.8 fps。为避免同一 target 的 screencast 互相覆盖，通过控制台 API 暂停转播、分别采样后恢复；没有刷新页面或修改登录内容。

| 采集方式 | 参数 | 实测 |
| --- | --- | --- |
| CDP screencast | 每帧，最大宽 1280，JPEG 65 | 166 帧 / 5.00 秒，33.19 fps |
| CDP screencast | 每帧，最大宽 1920，JPEG 80 | 151 帧 / 5.00 秒，30.17 fps |
| 顺序截图 | 原尺寸，JPEG 65 | 29 帧 / 5.02 秒，5.78 fps |

因此使用硬件渲染配合每帧 screencast 可以达到约 30 fps；顺序截图适合作为静止页面心跳，不适合作为主要直播采集。以上为真实登录页面的短窗口测试，长时间对局仍需观察。

自动操作所需的无损 PNG 另做了只读采集测试：招募页面默认编码平均 818.5 ms、约 1.16 MB；`optimizeForSpeed: true` 平均 478.6 ms、约 1.59 MB，耗时减少 41.5%。适配器对 PNG 默认启用速度优化，明确指定 `false` 及 JPEG 请求保持原样；自动和牌的一秒证据时效、倒计时的两秒采样上限均未放宽。PNG 解码模块也单独提取，四张真实截图逐像素等价，解码耗时减少约 12%–30%。

## 线上流程与输入适配

用户授权后已在服务器完成雀魂账号登录，成功进入大厅并自动创建友人房、执行三分钟招募。Linux 原生 CDP 需要在鼠标按下事件中携带 `buttons` 位掩码；鼠标移动回执后等待 100 ms，按下回执后再保持 100 ms，才能让原生渲染循环读到坐标与按键。按下保持的计时不能从发送前开始，否则慢回执会消耗整个间隔，实测导致网络弹窗确认无效；改为回执后保持后，同一坐标成功确认。适配器保持最终操作校验后立即发送按下；导航或断开会取消尚未完成的手势。凭据仅通过不回显标准输入用于这次登录，未写入项目、服务配置或日志。

Linux 4.0.51 的工具栏色值、结算按钮及奖励页文字与 Mac 的像素不同，现使用独立实测校准，未放宽 Mac 识别阈值。已实测确认结算、奖励页并返回房间，随后使用本人及三个电脑玩家建立新的采样局。开局门禁同时检查原生状态与牌桌画面，避免加载或入场动画尚未结束就启动出牌。已结束对局的 `1202` 提示要求错误码、正文和确认按钮全部匹配，并验证暂停、无执行器状态后才处理。

初期 `COUNTDOWN_LAYOUT_UNVERIFIED` 已通过真实 Linux 数字校准解决；开局时机器人正常推进导致的旧截图会被丢弃并有界重采。17:17（北京时间）的机器人对局中，台账首次记录两次 `confirmed`，桥接计数 `bridgeActionSends=2`，没有未决动作。后续时钟缓存版本在房间 69164 连续确认六次操作（两次碰、四次弃牌），报告 `sampleCount=1` 证明新窗口使用了新样本与已有单位校准。

针对五秒基础时间，整合版把计时单位校准与当前回合预算分开：首个窗口仍采双样本；同一页面、恢复代次、对局、小局、房间规则和画面版本内，五分钟内的新窗口可复用原单位校准，但必须读取新协议响应和实际倒计时。原双样本、当前像素一致性及墙钟与单调时钟偏移每次重新核验，截止时间只用当前窗口计算。未发送阶段的自然过期保留权威事件消费能力；只将精确匹配当前摸入牌和游标的原生超时摸切单列，不当作程序出牌成功。

第七次操作在发送前因 `AUTO_WIN_READBACK_STALE` 停止，台账明确为 `not-dispatched`、`not-sent`，发送计数仍为六、未决动作零。17:45:27 系统错误语音的 `health-automation` 条目记录 `outcome=completed`。监控退出旧房后自动建立新房，按生产设置招募三分钟；期间遇到一次开局同步竞争及一次提示框范围变化后继续恢复，最终房间 57733 的新局再次记录真实 `confirmed`。因此「实际操作 → 故障 → 错误语音 → 自动新房 → 招募 → 新局实际操作」链路已经跑通，干净画面保持 `live`。新局曾短暂受到误启动的并行测试负载影响，测试进程已被单独停止；不把该段作为无干扰的性能基准。

针对上述现象，连续模式开局的已知同步竞争改为三十秒总期限和可取消的短等待，每轮重采完整同步。自动和牌的常规读取改为从完整 PNG 中只解码实际字形和锚点，返回区域有明确边界，不填造未读取像素；CDP 仍采完整视口，避免裁剪影响转播。Debian 同图解码中位数从 109.84 ms 降至 34.16 ms，像素逐一相等。恢复阶段的完整牌桌验证保持不变。

系统错误语音已多次得到 `completed`，但这不代表外部语音接口永不失败。尚未完成无人值守长时运行或整场连续程序出牌验收，也未配置公开直播推流。
