# 倒计时过期与中途恢复（2026-11-08）

## 根因

房间 78397 的 `live-1fb0c004-c902-461b-8415-7bfded0a3485` 和房间 46482 的 `live-336f40de-03b0-4583-9a09-2ffcf45181f0` 均记录 `DEADLINE_EXCEEDED`、`executionDiagnostic=null`。5 秒且储备耗尽的窗口，第二次采样时已经耗时 2 秒，3 秒剩余扣除约 2.05 秒不确定性和 250 毫秒余量后，只剩约 700 毫秒。随后重复的自动和牌恢复、同步提交、控制屏障或冻结决策仍会消耗这份原始预算。原实现仅处理采样推导阶段的 `COUNTDOWN_EXPIRED`，没有覆盖后续过期。

此前仅跳过窗口也不完整：后续客户端摸切可能在最终报告中成为无法解释的己方弃牌，造成结算完整后仍阻断续局。异常后的重新接管还可能碰到小局切换中的空历史，返回 `SYNC_HAND_START_REQUIRED`；长时间停止会让旧桥接队列溢出，即使牌局结束也必须重装。

## 实现

- 同一小局已有开关验证时，刷新窗口使用新的只读画面核验；开关需恢复时仍走原完整恢复流程。小局、页面或连接变化不能沿用旧验证。
- 连续运行在 `ackTiming` 过期后仍提交权威同步，但不附带可执行 deadline。冻结、策略返回、准备或许可消费过期，仅在发送调用尚未开始、无未决动作时撤销许可并等待窗口推进；不重新采样或重发同一窗口。
- 过期窗口后紧接的同手、同来源步骤、同己方摸牌、非立直权威摸切，单列到 `expiredWindowDiscards`。不创造程序发送或确认。无关牌张、非摸切、立直、跨步骤及没有跳过窗口的弃牌仍不能解释；独立整场验收不放宽。
- 连续控制的可恢复异常在旧执行器释放后，可用同一数据库和房间建立新会话，重新同步当前小局，最多三次。故障报告的恢复资格来自页面暂停和真实共享台账检查；恢复前再次检查页面进程许可和对局摘要。原始 game UUID 不写入恢复诊断。
- 接管遇到暂时缺少完整小局历史时最多重采五次；持续失败仍报错。队列溢出／不可信桥接在重新启用时重装，包括旧牌局已结束的情况。
